# ADR-0044: 키워드 페이지 영속화 — 90일 보존 창 + 마지막 등장일 스냅샷

- Status: Accepted
- Date: 2026-08-15
- Deciders: yusik
- Related: [ADR-0002](./0002-frontend-nextjs-static-export.md), [ADR-0028](./0028-keyword-detail-aggregation.md), [ADR-0040](./0040-seo-structured-data-og-image.md), [ADR-0041](./0041-performance-cwv-font-loading.md), [ADR-0042](./0042-site-search.md), [ADR-0043](./0043-per-page-dynamic-og-images.md)

## Context (배경)

`/k/[keyword]` 는 `generateStaticParams` 가 **최신 스냅샷만** 훑어 만들어졌다(ADR-0028). 매일 약 40개 키워드 페이지가 생기고, 다음 빌드에서 그만큼 사라진다. 라이브에서 확인한 실제 상태 (2026-08-14, 3일 전 키워드):

```
404 | https://trends.jdgrid.com/k/여행/
404 | https://trends.jdgrid.com/k/반도체/
404 | https://trends.jdgrid.com/k/집/
```

sitemap 도 최신 키워드만 등재하므로, 구글은 **"매일 새 URL 40개 발견 → 다음날 404"** 를 83일째 반복해 왔다. 크롤 예산 낭비이자 사이트 품질 신호 악화이고, ADR-0043 으로 페이지별 OG 이미지를 붙여 공유 CTR 레버를 완성해 놓고도 정작 **공유된 링크가 하루 뒤 404 가 되는** 구조였다.

데이터는 이미 쌓여 있다 — `data/` 에 83일치 스냅샷(2026-05-21~08-13). 키워드는 하루 약 40개(신규 약 21개), 83일 누적 1,723개(중복 제거), 그중 2일 이상 재등장이 304개(미국 82일, 대통령 80일, trump 76일, iran 69일). 평균 등장 1.90일.

**선행 조건 — 사이드바 페이로드.** 착수 전 스파이크로 비용을 재다가, `layout.tsx` 가 `toSidebarData(loadLatest())` 로 `snapshot.trends` 를 통째로 client component 에 넘겨 **모든 페이지의 RSC 페이로드에 226KB** 가 실리고 있음을 발견했다(사이드바가 실제 렌더하는 건 0.6KB). 페이지 수를 43배로 늘리기 전에 고쳐야 할 문제라 별도 커밋(`5f1a3e4`)으로 선행 처리했다 — /k 페이지 362KB → 78KB, 빌드 20.1s → 13.5s.

→ 운영자 결정(2026-08-15, AskUserQuestion): **보존 창 90일 / 마지막 등장일 + 타임라인 / 사이드바 선행 수정 / OG·sitemap 모두 보존분 전부.**

## Decision (결정)

### 1. 보존 창 = 90일 (`KEYWORD_RETENTION_DAYS`)

- 최근 90일 스냅샷에 한 번이라도 등장한 키워드는 페이지를 유지한다. 현재 1,723개, 정상상태 약 1,900개.
- `/d` 페이지·sitemap 이 이미 쓰는 90일 slice 와 **같은 정책** — 타임라인이 링크하는 `/d` 가 항상 살아있음이 보장된다.
- 영구 보존은 기각: 하루 약 42파일(페이지+OG)씩 늘어 Cloudflare Workers 정적 자산 **무료 한도 20,000 파일**에 1년 남짓 뒤 도달한다.

### 2. 키워드 인덱스 (`src/lib/keyword-index.ts`)

- `buildKeywordIndex(snapshots)` 순수 함수 — `키워드 → 등장 일자[]`(최신 우선). 입력 순서 비의존(내부 정렬), 같은 날 kr/global 중복 기록 방지.
- **키는 소문자**, 값의 표기는 가장 최근 등장일 것. 대소문자만 다른 변형이 별도 페이지가 되면 대소문자 무시 파일시스템에서 충돌하기 때문(현재 데이터엔 충돌 0건이나 방어).
- `loadKeywordIndex()` 는 모듈 스코프 캐시 — 83개 스냅샷 파싱은 약 750ms·33MB 로 빌드 워커당 1회.
- `/k` 의 `generateStaticParams`(`params.ts`)·OG 라우트 핸들러·sitemap 이 모두 이 인덱스 하나를 공유.

### 3. 과거 키워드 페이지 = 마지막 등장일 스냅샷 + 등장 타임라인

- 페이지가 근거로 삼는 스냅샷은 `loadLatest()` 가 아니라 **마지막 등장일**(`loadKeywordSnapshot`). 그날의 검색량·Google 큐레이션·위키·매체 매칭이 그대로 살아난다.
- 최신 스냅샷 기준이 아니면 **시점 안내 배너** — "마지막으로 트렌드에 오른 {날짜} 기준입니다 · 오늘의 트렌드 보기 →".
- **타임라인 섹션** — 등장한 날짜 칩을 `/d/{date}/` 로 링크. 2일 이상 등장한 키워드(304개)에만 노출하고, 최대 14개까지 펼친 뒤 "외 N일" 로 접는다(미국 82일 대비). `등장 N일` 시그널 칩도 추가.
- 인덱스에 없는 키워드(보존 창을 벗어난 오래된 URL)는 기존 EmptyState 로 응답.

### 4. OG 이미지·sitemap 은 보존분 전부

- OG 는 보존 창 전 키워드에 생성 — 스파이크 실측 장당 약 7ms 로 비용이 사실상 없고, ADR-0043 의 공유 품질을 과거 URL 에도 유지한다. 배지 문구는 과거 페이지에도 맞도록 "오늘의 검색 트렌드" → **"검색 트렌드"**, 부제 날짜·검색량은 마지막 등장일 기준. 캐시버스터 `?v=` 도 마지막 등장일이라 과거 키워드는 URL 이 고정된다(= 캐시 적중).
- sitemap 도 전부 등재하되 `lastModified` 는 마지막 등장일, 최신이 아니면 `changefreq: monthly` / `priority: 0.3` 으로 낮춘다 — 신선도를 정직하게 신호.

## Consequences (결과)

**긍정**

- 색인된 키워드 URL 이 최소 90일 산다. 매일 40개씩 URL 을 버리던 구조 종료 — 크롤 예산 낭비·품질 신호 악화 해소.
- 색인 가능 페이지 40 → **1,723개**. sitemap 등재 URL 도 1,822개로 확대.
- 83일치 스냅샷이 처음으로 콘텐츠 자산이 됐다. 재등장 키워드 304개는 타임라인으로 `/d` 회유 동선까지 생김.
- ADR-0042 가 후속으로 남긴 "다일 검색"의 전제 조건 충족 — 검색 결과가 가리킬 과거 키워드 페이지가 이제 존재한다.

**부정 / 트레이드오프**

- 빌드 277 → **3,643 페이지**, 13.5s → **29.3s**. 산출물 `out/` 360MB, 파일 5,500개(Workers 무료 한도 20,000 의 27%). 여유는 있으나 **키워드 증가에 선형**이라 한도 추적이 필요하다.
- 사이드바가 매일 바뀌므로 1,723개 페이지 HTML 이 전부 매일 달라진다 = 매 빌드 전량 재업로드.
- 90일이 지난 키워드는 **다시 404 가 된다**. 창을 늘리는 선택은 파일 한도와의 교환이며, 한도에 근접하면 Paid 전환(100,000 파일)이나 창 축소로 대응한다.
- 과거 키워드 페이지는 그날의 스냅샷에 고정 — 이후 그 키워드로 새 기사가 나와도 반영되지 않는다(다시 트렌드에 오르면 마지막 등장일이 갱신되며 자동 반영).

**중립**

- 키워드 인덱스가 빌드 워커마다 83개 스냅샷(33MB)을 파싱 — 750ms 로 무시 가능. 스냅샷이 수백 개가 되면 스크레이프 시점 사전 인덱스 생성으로 옮길 수 있다.
- 하루만 등장한 키워드(약 80%)엔 타임라인이 보이지 않는다 — 보여줄 게 없으므로 의도된 생략.

## Alternatives Considered (대안)

- **30일 창** — 708개, 파일 약 1,500개로 가장 가볍다. 하지만 30일 뒤 다시 404 라 문제를 늦출 뿐이고, `/d`·sitemap 의 90일 정책과 어긋나 타임라인 링크가 깨질 수 있다. 기각(운영자 결정).
- **영구 보존** — SEO 관점 최선이나 Cloudflare 무료 한도(20,000 파일)에 약 1.2년 뒤 도달. 기각(운영자 결정).
- **마지막 등장일 스냅샷만 (타임라인 없음)** — 변경폭 최소지만 페이지가 '언젠가의 하루'로 고정돼 재방문 가치가 없다. 기각(운영자 결정).
- **전 등장일 기사 통합** — 정보량은 최대이나 미국(82일) 같은 키워드는 기사 수백 건 → 페이지 비대. 방금 226KB 페이로드를 걷어낸 방향과 정면으로 어긋난다. 기각(운영자 결정).
- **OG·sitemap 은 최신 일자만** — 빌드·파일 수는 아끼지만 과거 URL 공유 시 이미지가 제네릭이 되고(ADR-0043 무력화) 색인 유도도 약해진다. 기각(운영자 결정).
- **404 대신 `/d` 로 리다이렉트** — `_redirects` 로 가능하나 규칙 수 한도(2,100)와 키워드별 열거가 필요하고, 리다이렉트는 페이지 자체를 살리는 것보다 열등한 해법. 기각.
